# taba/wtc 0.2.8

Keep status observations scoped to the credentials that made them and current
for merged or declined PRs, create collections faster, resolve named tunnel
targets from the collection env, and trust posted Bitbucket review receipts.
Bitbucket catch-up can opt in to TWG; the default client stays `bb`.

No harness change is required. To try TWG for catch-up, set
`TABA_BITBUCKET_TRANSPORT=twg` in the environment or the control root's
`taba.env` and check the `bitbucket-client` row in `taba doctor`.

## Status

- **Separate authenticated status observations.** Switching forge credentials
  no longer reuses another context's cached metadata. Credentials whose context
  cannot be established locally still give live status, but their observations
  stay in one operation's memory and are never saved or shared. Offline
  previews remain local records, not current permission evidence. This is not
  an OS sandbox, and a remote permission change without a local credential
  change still waits for the usual observation ages.
  ([#441](https://github.com/lcorneliussen/taba/issues/441),
  [#443](https://github.com/lcorneliussen/taba/pull/443)).
- **Keep merged and declined PR facts current.** A stale open list no longer
  hides the PR of a checked-out branch whose upstream is gone; deferred reads
  name their reason and report the newest observation, Bitbucket merges record
  their merge time again, and `taba status --forge` no longer records merges
  or moves worktrees.
  ([#445](https://github.com/lcorneliussen/taba/issues/445),
  [#447](https://github.com/lcorneliussen/taba/pull/447)).

## Collections

- **Faster collection creation.** `taba new` fetches a collection's existing
  shared owners together instead of one after another, then checks the
  repositories out in the usual order; a fetch failure is still reported for
  its repository. A new workspace with tool panes settles its shells once
  instead of once more per added pane.
  ([#449](https://github.com/lcorneliussen/taba/issues/449),
  [#453](https://github.com/lcorneliussen/taba/pull/453)).

## Services

- **Named tunnels resolve `port_env` and `url_env` targets.** Since 0.2.5,
  `taba svc tunnel --name` and `start_with_service` accepted only a literal
  `x-wtc.url` and failed with "needs an explicit local URL/port"; they now
  read the collection env like `svc up`, and the error names the missing
  variable.
  ([#450](https://github.com/lcorneliussen/taba/issues/450),
  [#452](https://github.com/lcorneliussen/taba/pull/452)).

## Review

- **Trust posted Bitbucket reviews.** `review post` reads the comment id from
  the `bb` `comments add --json` envelope, and `review status` keeps comment ids
  exact and recognises `#comment-<n>` links, so a current passing review now
  opens `review ready`. Missing, conflicting or malformed ids stay pending.
  ([#444](https://github.com/lcorneliussen/taba/issues/444),
  [#446](https://github.com/lcorneliussen/taba/pull/446)).

## Catch-up

- **Opt-in TWG reads for Bitbucket catch-up.** With
  `TABA_BITBUCKET_TRANSPORT=twg`, catch-up reads enlisted Bitbucket PR state
  through TWG 1.x (1.4.4 or later); TWG failures stay unavailable and never
  fall back to `bb`. Only this catch-up read is migrated: status, review and
  other Bitbucket operations keep their current clients and ignore the
  selection. Operation contract:
  [docs/forges.md](https://github.com/lcorneliussen/taba/blob/main/docs/forges.md)
  ([#127](https://github.com/lcorneliussen/taba/issues/127),
  [#451](https://github.com/lcorneliussen/taba/pull/451)).
- **Choose the Bitbucket client once per machine.** `TABA_BITBUCKET_TRANSPORT`
  can be set in the control root's `taba.env`; the environment still overrides
  it, and an unreadable defaults file fails the operation instead of falling
  back. `taba doctor` shows the selected client, its source and, for TWG,
  whether the installed version is supported; the row is advisory and never
  fails doctor.
  ([#127](https://github.com/lcorneliussen/taba/issues/127),
  [#454](https://github.com/lcorneliussen/taba/pull/454)).
