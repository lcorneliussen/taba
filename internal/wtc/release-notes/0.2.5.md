# taba/wtc 0.2.5

This release adds managed named tunnels, makes control-root ownership explicit, and clarifies tunnel access in OpenClaw.

## Services

- **Manage named tunnels and retain stable registrations.** Receiving-local project defaults and collection overrides share one CLI/UI lifecycle, explicit exposure approval, scoped provider inputs, events, active host/origin publication, and interruption-safe owned cleanup. Dev Tunnel hosting uses the embedded helper and requires an existing Node 22+ runtime; other providers and status do not require Node. No npm installation is needed at runtime. ([#353](https://github.com/lcorneliussen/taba/issues/353), [#394](https://github.com/lcorneliussen/taba/pull/394))
- **Review cleanup and compatibility limits before adoption.** Managed manifests fence older clients before runtime teardown and worktree removal, but older pre-retirement hooks can still run. Unknown cleanup receipts stay pending and unresolved cleanup blocks retirement. Process identity and signaling use a bounded, non-atomic fallback where necessary. See the [service commands](https://github.com/lcorneliussen/taba/blob/v0.2.5/docs/commands.md) and [runtime lifecycle guidance](https://github.com/lcorneliussen/taba/blob/v0.2.5/internal/wtc/defaults/instructions/runtime.md).

## Secrets

- **Resolve control roots from receiving policy.** Project members and standalone collections use their own `.config` defaults; external sharing requires an exact receiving declaration. Remove stale root assignments or explicitly opt in before regenerating env. Discovery and launch checks enforce project boundaries. `env setup --repair-generated-roots --dry-run` previews recovery from stale generated roots without hooks or secret access. Retirement preserves nonempty private control data; provider credential isolation and global-store locking remain separate. ([#376](https://github.com/lcorneliussen/taba/issues/376), [#395](https://github.com/lcorneliussen/taba/pull/395))

## OpenClaw

- **Read tunnel access at a glance.** Tunnel links use neutral colours and small access glyphs: an open lock for public links, a closed lock for reported restricted access, and a question mark when access is unknown. ([#383](https://github.com/lcorneliussen/taba/issues/383), [#386](https://github.com/lcorneliussen/taba/pull/386))
