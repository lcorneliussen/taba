# taba/wtc 0.2.1

This patch improves terminal status readability, Bitbucket review presentation,
and release-note ranges, and adds reproducible native status captures.

## Status

- PR numbers and links align across rows, and checks, mergeability, and reviews
  keep a consistent order. Wide PR tables use readable headings; keyboard help
  explains unknown facts, pending checks, comments, and requested changes.
- Repository and PR cells share symbols: ✓ for clean mergeability, ● for
  waiting reviews, ✗ for requested changes, ✎ for comments, and · for unknown
  facts. Blocked mergeability uses the failure tone. Markdown output is unchanged.
- Compact repository rows reserve draft/conflict markers and full PR numbers
  before descriptive columns. Checks, mergeability, and review signals remain
  visible when the complete cell fits. Wide rows place draft/conflict labels
  after those signals; compact rows can show draft beside the number and use
  the merge signal for conflict. At very narrow widths, state and identity take
  priority over optional signals.
- The [status guide](https://github.com/lcorneliussen/taba/blob/v0.2.1/docs/status.md)
  explains Git, PR, review and build representations, provider coverage,
  build containment, freshness, and compact layouts. Checks, mergeability,
  and reviews are independent observations; a comment is not approval.

## Review

- Bitbucket review comments show verdict markers, compact concern coverage,
  and aggregate run totals. Open findings and unfamiliar sections remain
  visible, and the gate record is unchanged.

## Release notes

- Release-note ranges omit earlier prereleases, including when a stable
  release embeds candidate notes. A prerelease target still includes its own
  notes. Embedded and published notes use the same range rule.
- Exact-version selection, version lists, explicit unreleased notes, and empty
  future ranges retain their behavior. The default target remains the latest
  embedded numbered release. See the
  [release-note guide](https://github.com/lcorneliussen/taba/blob/v0.2.1/docs/release-notes.md).

## Development

- Native status captures use synthetic fixtures and structural text/layout
  assertions locally and in CI. Captures, screenshots, and the source/tool
  manifest remain review artifacts rather than committed assets.

## Compatibility and adoption

Both `taba` and `wtc` remain available. This patch requires no harness
configuration migration. Status facts still depend on provider coverage and
freshness; synthetic captures do not establish live provider behavior.
