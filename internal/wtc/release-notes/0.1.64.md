# wtc 0.1.64

## Fixes

- **Unsafe or conflicting alias state is refused without modifying linked targets or losing retirement guards.** Malformed retirement marker entries remain for inspection, and managed collections reject a blocked legacy guard-marker slot before teardown. Selected runtime and service directories are checked before planning or edits; commands refused for unsafe or conflicting alias state do not write service-change notifications. Safe partial service changes still notify status ([#201](https://github.com/lcorneliussen/wtc-cli/issues/201)).

## Rename

- **Review, retirement and status-watcher state are also read under taba names.** `.taba-review-mode` and `.taba-retired` take effect like their legacy markers, `.taba-reviews/` and `.taba-review-posted/` are read alongside the legacy directories, and retirement stops leases in `.taba-status-watchers/`. Default write locations and shared locks keep their legacy names; see [collection state](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.64/docs/rename-collection-state.md) ([#201](https://github.com/lcorneliussen/wtc-cli/issues/201)).

- **Runtime and local service state also work under `.taba/`.** A collection selects one home for `runtime` and `svc` together, and reads and writes there. `.wtc` wins when it holds state, a fresh collection still uses `.wtc`, and state under both is refused rather than risking a second runner or hidden services. `.wtc-runtime.lock` stays the shared lock; see [collection state](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.64/docs/rename-collection-state.md) ([#201](https://github.com/lcorneliussen/wtc-cli/issues/201)).

No state migration or manual rename is required. This is collection-state compatibility groundwork; the executable remains `wtc`.

## OpenClaw

- **Plugin upgrade recovery is clarified.** After replacing the CLI, run `wtc openclaw install` again; it normally reloads the plugin in the running gateway. Only if it reports that installation succeeded but the plugin did not reload, follow its instruction to restart the gateway. In either case, reload open Control UI tabs. This clarifies existing behavior; see [upgrade guidance](https://github.com/lcorneliussen/wtc-cli/blob/v0.1.64/docs/openclaw.md#upgrade).
