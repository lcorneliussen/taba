# taba/wtc 0.2.2

This maintenance release protects upgrade inputs, recovers verified GitHub
repository renames in status, and adds collection-local development following.
Bitbucket guidance follows its independently published 0.3.6 plugin.

## Upgrade

- **Protect edits through symlinked inputs.** Upgrade checks every selected
  version/config alias and its tracked target for uncommitted changes before
  writing inputs or refreshing the environment. Clean aliases within the harness
  remain supported; broken, escaping, untracked and non-file targets are refused.
  Existing selector precedence and independent duplicate files are preserved
  ([#258](https://github.com/lcorneliussen/taba/issues/258)).
- **Refuse upgrades during Git operations.** Finish or abort an in-progress
  harness merge, rebase, cherry-pick, revert or sequencer operation before
  upgrading.

## Added

- Collection-local `dev mode auto|on|off` follows selected source with fresh builds, persistent exit and idle status-TUI reload. Project conventions are explicit; review verification and the existing dev-build bypass remain isolated. One-shot installs retain their release-version fallback.
- `TABA_DEV_BUILD=off` bypasses local builds for both command names, with `WTC_DEV_BUILD` compatibility. OFF in either spelling wins; conflicting nonempty values warn. Upgrades do not opt a checkout into following, and older running status processes still need an explicit initial restart.
- Normal harness retirement guards against late dev publishers before final generated cleanup and stops cleanup if the guard or dev locks cannot be secured. Late failures retain a retryable guard when possible; ad-hoc reuse rules remain unchanged.

## Status

- Enlisted GitHub PRs recover incrementally on new-version scoped status
  refreshes after a repository rename. One live GraphQL operation must confirm
  equal opaque repository IDs at the old name, current name and PR base, with
  matching canonical names, PR number and URL. Partial/error responses leave
  metadata unchanged. Bitbucket rename mismatches remain fail-closed; automatic
  recovery for that forge is not included.
  ([#358](https://github.com/lcorneliussen/taba/issues/358)).
- Recovery and due live PR detail receive rotating request priority under the
  existing forge allowance. A failed job yields to the next eligible row;
  cache hits, local preflight failure and token/cooldown denial do not advance
  the cursor. There is at most one issued repair operation per forge per scoped
  refresh. No provider identity or completed proof is cached. Active repair rows
  start ahead of history; stored row order, concurrent edits and settled merge
  facts are preserved. Workspace status sweeps remain read-only across
  collection boundaries.

## Upgrades

- After the harness upgrade PR merges, run `taba upgrade --rollout` with the
  installed new version. Eligible collections now reload their verified status
  panes through the exact installed mise pin, with automatic installs and dev
  handover disabled for that process. A stale pane PATH cannot pick the old
  binary. Dirty worktrees,
  in-progress operations, busy owners and unrelated pane processes retain
  their existing safeguards. Failed environment or tool installation leaves
  the old status pane running. A pin proposal and release-note rendering do
  not restart panes or repair PR metadata. Active dev following or an unreadable
  follow policy leaves that status pane for its owner (`needs-owner`); explicitly
  choose `dev mode off` before a stable installed-target rollout.

## OpenClaw

- **Bitbucket operator guidance follows the published 0.3.6 plugin.** Install
  that independent plugin separately, connect personal accounts through
  **Bitbucket** in the Control UI sidebar after signing in to OpenClaw, and
  use `--no-enable` when upgrading to preserve enablement, allowlists and
  denylists. Reload only an enabled installation; intentionally disabled
  installations stay disabled. Existing personal logins and settings are
  reused, and OpenClaw 2026.10.2 remains the minimum supported host.
