# taba/wtc 0.2.11

A small follow-up release. Repository rows in the status table stay one line
each, also with collection base overrides; open PRs are refreshed before old
merged and closed ones; Git refs are always fully qualified; and the upgrade
doctor runs the selected release's own executable. Each change is a bounded
part of its issue. The dense-row work covers repository rows only: PR rows and
service rows are not yet held to the same one-line contract, which remains open
in [#534](https://github.com/lcorneliussen/taba/issues/534),
[#426](https://github.com/lcorneliussen/taba/issues/426) and
[#477](https://github.com/lcorneliussen/taba/issues/477).

**Upgrade notes.** Install the release; no pin or configuration changes are
needed when every development ref in the harness's `.harness-repos.yml` is
`origin/<branch>` or fully qualified, which is what the docs and generated
registries write. A bare `default_ref: main` is now refused with its value
named: catch-up fails that repository and status fails its collection, instead
of silently following a clone-time local branch that fetches never move.
Forge CLI reads (`gh`, `bb`, `twg`) now read their output back from a temporary
file, so they need a writable temporary directory. Only the doctor changed:
the upgrade's `release-notes` step and the status-pane reload command still
invoke a bare `wtc`.

## Status

- **One line per repository, also with base overrides.** A `*` after the `↓`
  count marks a collection base override. Its ref and reason moved from under
  the row to `?` help (one entry per distinct reason), Markdown, JSON and
  `repo base show`; plain output adds one note line pointing there
  ([#534](https://github.com/lcorneliussen/taba/issues/534),
  [#544](https://github.com/lcorneliussen/taba/pull/544)).
- **Open PRs are refreshed before old terminal ones.** Never-observed and active
  PRs are read first; merged, declined, closed and superseded PRs are rechecked
  only after them, so a refresh deadline no longer leaves new drafts unobserved.
  A PR that gets no turn keeps its last observed state, marked deferred
  ([#535](https://github.com/lcorneliussen/taba/issues/535),
  [#541](https://github.com/lcorneliussen/taba/pull/541)).

## Collections

- **Git refs are always fully qualified.** Catch-up, status, worktree
  checkout and the gateway's catch-up give Git `refs/heads/<branch>` and
  `refs/remotes/origin/<branch>`, so a tag or branch named like the development
  branch no longer stands in for it. A development ref must be
  `origin/<branch>` or fully qualified: a bare `default_ref: main` now fails
  with its value named, instead of following a local branch that fetches never
  move. A sandbox's catch-up merge commit names `refs/remotes/origin/<base>`
  ([#497](https://github.com/lcorneliussen/taba/issues/497),
  [#506](https://github.com/lcorneliussen/taba/pull/506)).

## Upgrade

- **The upgrade doctor runs the selected release.** After `upgrade` or
  `--rollout`, the advisory doctor runs the `taba` (or, for older releases,
  `wtc`) executable inside the directory `mise where` reports for the selected
  release, so another installed tool's `wtc` earlier on the path can no longer
  answer in its place and fail the version check. If that directory holds no
  such executable, the doctor reports `unavailable` and runs nothing
  ([#533](https://github.com/lcorneliussen/taba/issues/533),
  [#540](https://github.com/lcorneliussen/taba/pull/540)).
