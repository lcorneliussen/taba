# taba/wtc 0.2.4

This release makes PR status refresh more reliable, adds a migration checklist for the taba rename, and improves OpenClaw repository actions and local-edit recovery.

## Status

- **Refresh merged PRs reliably.** Bitbucket refresh preserves confirmed merges and labels lookups deferred by shared request limits. Unconfirmed PR state blocks branch actions and retirement instead of treating stale observations as current. ([#319](https://github.com/lcorneliussen/taba/issues/319), [#374](https://github.com/lcorneliussen/taba/pull/374))

## Rename and harness adoption

- **Skills are named `taba-*`, with `wtc-*` compatibility shims through 0.2.x.** Old-name harness overrides and section patches still apply; the renamed skill points to an old-name override while it exists. Rename override folders and their `name:` fields together, move section patches and base digests, and review any reported base drift. ([#351](https://github.com/lcorneliussen/taba/issues/351), [#352](https://github.com/lcorneliussen/taba/pull/352))
- **`taba open` uses `taba status --tui` and `taba browse` for collections pinned at 0.2.0 or later.** Older pins keep `wtc`. Newly rendered collections start their agent with `/taba-start`.
- **`taba harness init` writes `.taba-version` and `taba.toml`** and requires `--cli-version` 0.2.0 or later. A harness with only `.taba-version` seeds new collections with `SCOPE.md`; other harnesses keep `WTC-SCOPE.md`. Existing scope files are not moved. Upgrade and roll out a compatible CLI before renaming harness files, and update tooling that reads old names. See the [configuration migration](https://github.com/lcorneliussen/taba/blob/v0.2.4/docs/rename-config-inputs.md).
- **`taba doctor` reports remaining wtc conventions and a migration step for each.** `taba doctor --all` checks the workspace, including when run from its root; `taba conventions` lists supported names. Findings do not fail `doctor` during 0.2.x, and conventions without a replacement are marked as waiting. Follow the [migration order and compatibility table](https://github.com/lcorneliussen/taba/blob/v0.2.4/docs/conventions.md); renaming is optional during 0.2.x. ([#375](https://github.com/lcorneliussen/taba/issues/375), [#377](https://github.com/lcorneliussen/taba/pull/377))

## OpenClaw

- **Repository fact cells keep their dimensions while actions run.** Narrow folded facts align with bulk controls; click `±N` to request local commits or a column's `±` for eligible repositories together. Hover, pending, and brief observed-success feedback use the same space. Publication remains a separate action. See [fact actions](https://github.com/lcorneliussen/taba/blob/v0.2.4/docs/openclaw-fact-actions.md). ([#342](https://github.com/lcorneliussen/taba/issues/342), [#343](https://github.com/lcorneliussen/taba/pull/343))
- **Catch-up preserves staged, unstaged, and untracked edits in a pinned recovery copy**, restoring staging after the merge. Incoming tracked paths that would replace ignored local data are refused even on clean checkouts. Failed restoration stays explicit and blocks blind retries; unfinished operations and unverified recovery block sandbox delivery and worker merges.
- **Recovery completion verifies saved edit layers before continuing.** It preserves legitimate partially staged marker text, decodes Git-quoted paths, and refuses newly introduced markers or unverifiable diffs. A verified finish archives only its exact active marker and retains backups. Matching native receipts settle recovery feedback and reservations across views without retrying, committing, or publishing.
- **Action reservations prevent duplicate mutations across views.** Catch-up previews its target rows on hover or focus; pending or unconfirmed commit cells open action details with an agent-help handoff that does not retry the operation. Commit controls recheck the action plan and recovery; partial progress retains its reservation, and push preparation rechecks it. Missing or late responses stay unconfirmed and cannot revive completed work or release a newer request. Explicit acknowledgement releases the original request across views.
- **PRs published from the Collection panel appear in collection tracking**, with a readable preview before confirmation. If tracking needs a retry, refresh updates the record without publishing again. ([#369](https://github.com/lcorneliussen/taba/issues/369), [#370](https://github.com/lcorneliussen/taba/pull/370))
