# taba/wtc 0.2.6

This release adds collection-local repository bases and improves status, review,
service startup and OpenClaw controls. Both `taba` and `wtc` remain supported.

## Review

- **Read Bitbucket review comments consistently.** Use the common bounded comment-list options supported by community CLI versions 1.8.3 and 2.2.1, and decode comment text before checking prior findings. Unproven collections and PRs with 1,000 or more comments keep inline posting pending. This partially addresses [#60](https://github.com/lcorneliussen/taba/issues/60) ([#409](https://github.com/lcorneliussen/taba/pull/409)); creation envelopes, resolution compatibility and live provider certification remain open.

## Workspace opening

- **Recognize interrupted agent startup.** When Herdr reports an agent is not
  ready, verify its live identity and report its startup state without repeated
  starts or sending a first prompt. Finish startup manually in the agent pane;
  genuine launch failures and mismatched identities remain errors.
  ([#242](https://github.com/lcorneliussen/taba/issues/242),
  [#402](https://github.com/lcorneliussen/taba/pull/402)).

## OpenClaw

- **Copy complete card diagnostics.** Click or keyboard-activate the diagnostic to copy its full text, with a manual-copy field when clipboard access fails. Keep diagnostic hover and focus stable across refreshes; open full details with the Activity action.
  ([#243](https://github.com/lcorneliussen/taba/issues/243), [#403](https://github.com/lcorneliussen/taba/pull/403)).

- **Reuse an active manual status refresh.** Repeated Refresh clicks across the collection card and panel share one read and one activity entry. Reloads after actions still request fresh status. Superseded or closed-view refresh observations no longer appear as unconfirmed actions or offer agent help. Missing or cancelled status responses, including background and post-action reads, report failure. This addresses part of [#245](https://github.com/lcorneliussen/taba/issues/245) ([#410](https://github.com/lcorneliussen/taba/pull/410)).

- **Make tunnel keyboard focus easier to see.** Use the host theme's solid focus ring for the Add tunnel trigger and provider choices in light and dark modes. ([#255](https://github.com/lcorneliussen/taba/issues/255), [#411](https://github.com/lcorneliussen/taba/pull/411)).

- Refuse repository-add plans when an existing local collection retains a link
  to a missing checkout, before recording publication metadata. Ownership and
  recovery availability remain unknown; healthy duplicate plans remain possible.
  ([#327](https://github.com/lcorneliussen/taba/issues/327),
  [#406](https://github.com/lcorneliussen/taba/pull/406)).

- **Show default service ports correctly.** Display HTTPS loopback services as port 443 and associate HTTP(S) services with gateway portals using their scheme's default port when omitted or written explicitly. Explicit nondefault ports are preserved.
  ([#366](https://github.com/lcorneliussen/taba/issues/366), [#407](https://github.com/lcorneliussen/taba/pull/407)).

- Replace the Collection label with the running Taba version in card and sidebar headers. Narrow cards keep the logo and version; full CLI and plugin build details remain available on hover. ([#422](https://github.com/lcorneliussen/taba/issues/422), [#423](https://github.com/lcorneliussen/taba/pull/423)).

## Status

- **Bound native service status reads.** Runner status and task listing share a
  five-second budget per collection, including returned action snapshots; an
  unavailable task observation reports `unknown` with an error. Action and
  readiness command limits are unchanged.
  This is a partial diagnostic improvement for
  [#284](https://github.com/lcorneliussen/taba/issues/284)
  ([#412](https://github.com/lcorneliussen/taba/pull/412)).

- **Show branch-discovered PRs in the inventory.** Open and draft PRs appear
  marked **not enlisted**, with an explicit enlist command. Discovery stays
  transient and does not write PR enlistment or grant merge/checkout authority.
  ([#337](https://github.com/lcorneliussen/taba/issues/337),
  [#399](https://github.com/lcorneliussen/taba/pull/399)).

- **Retry status reload on transient foreground lookup errors.** Reload keeps its bounded waits and requires a verified shell before sending a command and an observed status process before reporting success. Exhausted waits suggest inspecting the pane before retrying.
  ([#380](https://github.com/lcorneliussen/taba/issues/380), [#398](https://github.com/lcorneliussen/taba/pull/398)).

- **Budget native Bitbucket HTTP redirects.** Redirect hops now spend the shared forge allowance, respect cooling and confirmation reservations, and reject unsafe targets. Incomplete reads remain deferred or partial. External CLI transport retries remain outside this fix. ([#404](https://github.com/lcorneliussen/taba/issues/404), [#405](https://github.com/lcorneliussen/taba/pull/405)).

## Upgrade rehearsal

- **Report failed observations and verify release selection.** Rehearsals now fail when a required snapshot command fails, retain its diagnostics, and validate release versions and executable paths inside the private mise installs tree before running them. Probes use the throwaway collection directory, and release commands bypass local dev handover. Invalid target releases skip dependent catch-up and registry follow-up steps. Hooks and caller authentication retain their existing trust boundary. ([#332](https://github.com/lcorneliussen/taba/issues/332), [#414](https://github.com/lcorneliussen/taba/pull/414)).

## Collections

- **Choose a local development base per repository.** Set, show or clear a base
  with a human reason; creation, status, catch-up, browse and review defaults
  resolve it in the receiving collection while production refs stay registry-owned.
  Existing PR destinations remain authoritative. OpenClaw local checkout bases
  do not change gateway publication destinations; sandbox bases must match the
  authorized destination.
  ([#349](https://github.com/lcorneliussen/taba/issues/349),
  [#416](https://github.com/lcorneliussen/taba/pull/416)).

## Services

- **Keep first-use tunnel controls usable.** Disabling a named tunnel before the first service start no longer leaves a notification file that blocks runtime creation. Normal setup also recovers the empty notification left beside a valid owned tunnel journal by 0.2.5; unrelated or unsafe state remains refused. Unconfigured or invalid runtime state waits for the next status poll; configured runtimes still notify immediately. ([#353](https://github.com/lcorneliussen/taba/issues/353), [#401](https://github.com/lcorneliussen/taba/pull/401))

## Tunnel client availability

- Reject non-executable files, directories and broken symlinks in gateway PATH tunnel-provider badges. Collection responses and setup clicks distinguish missing, unusable and unknown lookup results, explicitly scoped to gateway PATH. Actual collection runtime capability still depends on configured executable, helper or socket inputs; this lookup does not verify authentication, reachability or running tunnels. Part of [#365](https://github.com/lcorneliussen/taba/issues/365) ([#400](https://github.com/lcorneliussen/taba/pull/400)).

## Fixes

- Re-enlisting a PR preserves its existing title when empty and its URL when omitted, including URL-only references and verified repository aliases. Explicit values still replace metadata, and omitted branches retain their existing checkout defaults. Native publication retries preserve an already recorded title. ([#378](https://github.com/lcorneliussen/taba/issues/378), [#413](https://github.com/lcorneliussen/taba/pull/413)).

## Documentation

- **Clarify tool config scoping.** Explain directory-presence opt-in, environment precedence and the limits of filesystem routing: token variables and secure stores can remain eligible. Preserve stores when changing configuration instead of deleting them. Generator, authentication and migration behavior are unchanged; broader credential isolation remains open. ([#382](https://github.com/lcorneliussen/taba/issues/382), [#408](https://github.com/lcorneliussen/taba/pull/408)).

## Upgrade guidance

Update the CLI pin and harness compatibility range together, preserve local hooks
and overlays, and review `taba skills diff` before regenerating configuration.
For OpenClaw changes, reinstall the plugin from the new CLI with
`taba openclaw install`, then reload open Control UI tabs. The plugin requires
OpenClaw 2026.10.2 or later. See the
[0.2.6 upgrade procedure](https://github.com/lcorneliussen/taba/blob/v0.2.6/docs/release-notes.md#upgrade-a-harness)
for the intended tagged source when published.
