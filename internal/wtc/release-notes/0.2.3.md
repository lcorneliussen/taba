# taba/wtc 0.2.3

This maintenance release fixes fresh-sandbox project discovery, gateway
repository ports, repository-name layout and review activity checks. Terminal
status keeps a known PR merge visible when full landing is still unknown.

## OpenClaw

- **Discover projects from a fresh sandbox.** `taba projects` identifies the
  agent from its running sandbox container before a conversation has a managed
  worktree. `sandboxGit.projectsByAgent` still controls access and denies by
  default. Git, session and delivery routes still require the managed worktree
  ([#354](https://github.com/lcorneliussen/taba/issues/354)).
- **Repair missing gateway repository ports on status refresh.** The selected
  project's verified GitHub or Bitbucket repository identity supplies missing
  port and alias metadata, including supported SCP remotes with or without an
  SSH username. Full identity matching and strict path validation remain
  required. Explicit local port/alias settings, legacy port names and the
  allocated port block are preserved. Refresh repairs the generated environment
  without restarting services; running services keep their launch environment
  until explicitly restarted. See
  [gateway ports](https://github.com/lcorneliussen/taba/blob/v0.2.3/docs/openclaw-gateway-ports.md)
  ([#315](https://github.com/lcorneliussen/taba/issues/315)).
- **Give repository names more room.** Names use available width before spare
  space goes to the branch column, with a limit for unusually long names.
  Hovering the repository icon or label reveals its full identity when clipped.
  An action error no longer shifts the wide branch columns
  ([#363](https://github.com/lcorneliussen/taba/issues/363)).

## Status and review

- **Keep known PR merges explicit.** A merged PR on a retained branch shows
  `merged` in STATE when full landing is unknown, with the separate full-landing
  hint retained. Merge observation and landing uncertainty do not authorize
  branch cleanup. This does not complete broader merge-landing or default-branch
  verification work
  ([#229](https://github.com/lcorneliussen/taba/issues/229)).
- **Wait for exact-head hosted review activity.** Paginated REST check-runs
  supplement the PR status rollup, so an active Copilot or Cursor check omitted
  from the rollup still delays local review. Incomplete evidence and changing
  PR heads remain errors. Completed checks alone do not establish review
  coverage or approval
  ([#361](https://github.com/lcorneliussen/taba/issues/361)).

## Gateway adoption

Upgrade the gateway's CLI first, then run `taba openclaw install` to refresh the
matching path-installed plugin. Installation normally reloads the running
plugin; if it reports that reload failed, follow its gateway restart instruction.
Refresh open Control UI tabs afterward. `openclaw plugins update` skips this
path-installed plugin.

For a gateway built by CI/CD, bump the binary version and rebuild and roll out
the image with its matching embedded plugin. Follow the
[upgrade guide](https://github.com/lcorneliussen/taba/blob/v0.2.3/docs/openclaw.md#upgrade)
and [image guide](https://github.com/lcorneliussen/taba/blob/v0.2.3/docs/openclaw.md#gateway-image-and-cicd).
The independently published Bitbucket plugin remains at 0.3.6; this CLI release
does not require a new Bitbucket plugin release.
